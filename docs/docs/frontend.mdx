# Frontend

The TanStack Start app in `frontend/` is the web UI for coaches. It is a TypeScript Vite app with file-based routing. Today it serves a root landing page, a `/health` page that calls the backend health endpoint, an `/accounts/create` page that posts to `POST /accounts`, a `/login` page that posts to `POST /login`, and a `/me` profile page that calls `GET /me` when a session `token` is present; logout, broader auth for every route, and most domain features are not wired yet.

By default the dev server listens on [http://localhost:3000](http://localhost:3000). The `backend/` service defaults to port `8000`, and the docs site to `3001`.

## Requirements

- [Node.js](https://nodejs.org/) 26 (see [`frontend/.nvmrc`](frontend/.nvmrc); same as the docs site)

## Install

From the repository root:

```bash
cd frontend
npm install
```

## Run locally

```bash
cd frontend
npm run dev
```

Starts the app at [http://localhost:3000](http://localhost:3000). The root route renders **AI Football Coach**.

## Local backend for `/health`

The `/health` page fetches the backend `GET /health` endpoint and shows the status (or an unavailable message if the request fails).

1. Start the backend (defaults to [http://127.0.0.1:8000](http://127.0.0.1:8000)):

```bash
cd backend
cargo run
```

2. Start the frontend (`npm run dev` as above).

3. Open [http://localhost:3000/health](http://localhost:3000/health).

By default the page uses backend base URL `http://127.0.0.1:8000` (so it calls `http://127.0.0.1:8000/health`). Override with `VITE_BACKEND_BASE_URL` (copy `frontend/.env.example` → `frontend/.env`):

```bash
cd frontend
cp .env.example .env   # optional; gitignored
npm run dev
```

Local browser calls need CORS. The backend defaults to allowing Vite on port 3000 (`http://localhost:3000` and `http://127.0.0.1:3000`). To allow other origins, set `CORS_ALLOWED_ORIGINS` in `backend/.env` (comma-separated); see `backend/.env.example`. The `/health` JSON contract is unchanged.

The same local `/health` setup is summarized in [`frontend/README.md`](../../frontend/README.md).

## Local backend for `/accounts/create`

The `/accounts/create` page posts JSON `{ "email", "password" }` to the backend `POST /accounts` endpoint (`Content-Type: application/json`). On `201` it shows a success state with the created account `email` (never the password). On `400` / `409` or if the backend is unreachable, it shows a clear error and does not pretend the account was created.

1. Start the backend (defaults to [http://127.0.0.1:8000](http://127.0.0.1:8000)) as in the `/health` section above.

2. Start the frontend (`npm run dev` as above).

3. Open [http://localhost:3000/accounts/create](http://localhost:3000/accounts/create).

By default the page uses backend base URL `http://127.0.0.1:8000` (so it calls `http://127.0.0.1:8000/accounts`). Override with `VITE_BACKEND_BASE_URL` the same way as `/health`. The CORS notes above apply to browser `POST /accounts` calls as well.

The same local `/accounts/create` setup is summarized in [`frontend/README.md`](../../frontend/README.md).

## Local backend for `/login`

The `/login` page posts JSON `{ "email", "password" }` to the backend `POST /login` endpoint (`Content-Type: application/json`). On `200` with `{ "id", "email", "token" }` it persists the `token` in `sessionStorage` and shows a logged-in state with the coach `email` (never the password). On `401` or other failure (including unreachable backend), it shows a clear error and leaves the user logged out.

There is no account-creation UI on this page. Create an account first via `/accounts/create` (or `POST /accounts` with curl) before logging in.

1. Start the backend (defaults to [http://127.0.0.1:8000](http://127.0.0.1:8000)) as in the `/health` section above.

2. Start the frontend (`npm run dev` as above).

3. Create an account at [http://localhost:3000/accounts/create](http://localhost:3000/accounts/create) if you do not already have one.

4. Open [http://localhost:3000/login](http://localhost:3000/login) and submit email and password.

By default the page uses backend base URL `http://127.0.0.1:8000` (so it calls `http://127.0.0.1:8000/login`). Override with `VITE_BACKEND_BASE_URL` the same way as `/health`. The CORS notes above apply to browser `POST /login` calls as well.

The same local `/login` setup is summarized in [`frontend/README.md`](../../frontend/README.md).

## Local backend for `/me`

The `/me` profile page is only reachable when a session `token` from `/login` is present in `sessionStorage`. When logged in it calls backend `GET /me` with `Authorization: Bearer <token>` and displays the returned `id` and `email`. On `401` or other failure (including unreachable backend), it shows a clear error and does not invent profile fields. If the user is not logged in, the route redirects to `/login`.

1. Start the backend (defaults to [http://127.0.0.1:8000](http://127.0.0.1:8000)) as in the `/health` section above.

2. Start the frontend (`npm run dev` as above).

3. Log in at [http://localhost:3000/login](http://localhost:3000/login) first so a `token` is stored.

4. Open [http://localhost:3000/me](http://localhost:3000/me).

By default the page uses backend base URL `http://127.0.0.1:8000` (so it calls `http://127.0.0.1:8000/me`). Override with `VITE_BACKEND_BASE_URL` the same way as `/health`. The CORS notes above apply; local CORS allows the `Authorization` header for this Bearer call.

The same local `/me` setup is summarized in [`frontend/README.md`](../../frontend/README.md).

## Tests

Acceptance checks are TypeScript Vitest files under `frontend/tests/`.

```bash
cd frontend
npm test -- --run
```

`quality-tests` in the software factory runs this same command.

## Quality gates

Biome handles lint and format. TypeScript covers typecheck.

```bash
cd frontend
npm run format:check   # Biome format (CI / factory)
npm run format         # Biome format --write (local fix)
npm run lint           # Biome lint
npm run typecheck      # tsc --noEmit
```

`quality-static` runs `format:check`, `lint`, and `typecheck` when those scripts are present. GitHub Actions (`.github/workflows/frontend.yml`) enforces the same on PRs that touch `frontend/`, plus `npm test -- --run` and `npm run build`.

## Layout

| Path | Role |
|------|------|
| `frontend/package.json` | Scripts (`dev`, `test`, `build`, `lint`, `format`, `format:check`, `typecheck`) and TanStack Start deps |
| `frontend/biome.json` | Biome lint + format config |
| `frontend/.nvmrc` | Node 26 for local and CI |
| `frontend/vite.config.ts` | Vite + `@tanstack/react-start` plugin |
| `frontend/src/routes/__root.tsx` | Document shell / head |
| `frontend/src/routes/index.tsx` | Root (`/`) page |
| `frontend/src/routes/health.tsx` | `/health` page (calls backend `GET /health`) |
| `frontend/src/routes/accounts.create.tsx` | `/accounts/create` page (calls backend `POST /accounts`) |
| `frontend/src/routes/login.tsx` | `/login` page (calls backend `POST /login`) |
| `frontend/src/routes/me.tsx` | `/me` profile page (calls backend `GET /me`) |
| `frontend/src/router.tsx` | Router factory |
| `frontend/tests/` | TypeScript Vitest acceptance checks for the scaffold |
